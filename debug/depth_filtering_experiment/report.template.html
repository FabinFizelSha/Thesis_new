What the filter does real librealsense SDK, not a reimplementation

Numpy depth frames decoded from the bag are injected into a rs.software_device — a synthetic sensor the compiled pyrealsense2 SDK will accept frames from — so Intel's own spatial, temporal, and hole-filling filters process this data exactly as they would a live D455's stream. RGB is not involved in this stage; librealsense's post-processing filters are depth-only. (RGB is used earlier, in the pixel-matching/alignment stage that produced this bag's aligned-depth topic in the first place.)

Processing order per frame

raw uint16 depth→ range gate [0.30, 6.00]m→ depth→disparity→ spatial filter→ temporal filter→ disparity→depth→ hole filling

Disparity-domain processing (rather than filtering metric depth directly) is Intel's own design: stereo depth noise grows roughly with the square of range, so smoothing behaves more uniformly across near/far pixels in disparity space. The temporal filter is stateful — one filter instance is reused for all 2,678 frames in order; a fresh instance per frame would silently disable cross-frame persistence.

Caveats

Depth-only. This filter stage does not use RGB. It runs the same post-processing a live D455 would run on its own depth stream. RGB's role in this bag is upstream, in pixel-matching depth to the rectified color grid.

No ground truth. All metrics here are internal consistency checks (coverage, self-agreement, local smoothness) — there is no independent, higher-accuracy depth reference for this bag to compute true error against.

Temporal settings were deliberately not maxed for the moving-platform reason in §2's parameter table; a stationary-sensor recording could likely push temporal smoothing further without the same motion-smearing risk.

A separate, unrelated finding surfaced while tracing topics for this pipeline: rsg_pipeline_go1.yaml's rgb: key points at the raw (distorted) color topic while depth is aligned to the rectified geometry — a real geometric mismatch, but orthogonal to this filtering experiment and not yet fixed as of this report.
