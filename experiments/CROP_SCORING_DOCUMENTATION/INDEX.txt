PARAMETER QUICK REFERENCE
================================================================================

All in: src/rsg/nodes/support/phase1/tracking_crop_manager.py (lines 26-40)

Object Prominence (Pixel Metric):
  PIXEL_NORMALIZATION_BASE = 100000
    └─ Raise to penalize small objects more
    └─ Lower to make small objects more competitive

Image Quality (Sharpness Metric):
  SHARPNESS_DIVISOR = 400.0
    └─ Lower to require sharper crops
    └─ Raise to be more forgiving of blur
  SHARPNESS_SKIP_THRESHOLD = 0.1
    └─ Skip Laplacian if pixel_score < this
    └─ Saves computation for small crops
  DEFAULT_SHARPNESS = 0.5
    └─ Assumed sharpness when Laplacian skipped

Framing Quality (Margin Metric):
  MARGIN_EDGE_PROXIMITY = 3
    └─ Pixels within this distance count as touching edges
    └─ Raise for stricter edge detection

Update Control:
  HYSTERESIS_MARGIN = 0.005
    └─ 0.5% improvement required
    └─ Raise (e.g., 0.010) for stricter filtering
    └─ Lower (e.g., 0.002) for more frequent updates

Metric Weights:
  WEIGHT_PIXEL = 2.0      (40% of score)
  WEIGHT_SHARPNESS = 2.0  (40% of score)
  WEIGHT_MARGIN = 1.0     (20% of score)
    └─ Adjust to change metric importance

HOW TO MODIFY
================================================================================

To adjust configuration:
  1. Edit tracking_crop_manager.py (lines 26-40)
  2. Run: colcon build --packages-select rsg
  3. Run: ros2 launch rsg phase1_launch.py
  4. Check: debug/best_crop_analysis/crops/session_*/crop_progression_diagnostics.csv

To understand impact:
  1. Compare TEST_SESSION_RESULTS.csv (baseline)
  2. Analyze new session_*/crop_progression_diagnostics.csv
  3. Count updates, check deltas, review margin scores

Example adjustments:
  - Too many marginal updates? Increase HYSTERESIS_MARGIN
  - Margin scores too high? Increase MARGIN_EDGE_PROXIMITY
  - Small objects rejected? Decrease PIXEL_NORMALIZATION_BASE
  - Need better framing? Increase WEIGHT_MARGIN

See SOURCE_CODE_REFERENCE.md for detailed examples and debugging.

SUPPORT & TROUBLESHOOTING
================================================================================

Issue: Too many trivial updates (0.001% improvements accepted)
  → Increase HYSTERESIS_MARGIN from 0.005 to 0.010
  → See: SOURCE_CODE_REFERENCE.md (Debugging section)

Issue: Margin scores seem wrong (too high or too low)
  → Adjust MARGIN_EDGE_PROXIMITY (3 to 4-5 pixels)
  → Check sample_crops/ to verify visually
  → See: 01_DESIGN_DOCUMENT.md section 4 (Margin Score Evolution)

Issue: Small objects being rejected
  → Increase WEIGHT_PIXEL or decrease PIXEL_NORMALIZATION_BASE
  → Or increase PIXEL_NORMALIZATION_BASE to 150000
  → See: SOURCE_CODE_REFERENCE.md (Configuration examples)

Issue: Need to understand why specific crop was accepted/rejected
  → Look up track_id in TEST_SESSION_RESULTS.csv
  → Check margin/pixel/sharpness values for that frame
  → Compare against HYSTERESIS_MARGIN threshold
  → See: 01_DESIGN_DOCUMENT.md section 7 (Formulas)

Issue: Rebuild didn't work
  → Ensure you modified tracking_crop_manager.py, not phase1.py
  → Run: colcon build --packages-select rsg
  → Check for syntax errors in your edits
  → See: SOURCE_CODE_REFERENCE.md (Rebuilding section)
